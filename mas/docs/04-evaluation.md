# 04 — Evaluation Criteria Mapping

## How MAS QHomemart Maps to Competition Evaluation Criteria

This document maps the system design and implementation to the criteria typically
used to evaluate multi-agent system prototypes in a competition context. Each
criterion is explained in terms of what the system demonstrates and where to look
for evidence in the codebase.

> **Prototype scope:** All agent logic runs as deterministic local TypeScript functions
> using dummy modular data. No real QHomemart production integration, no real inventory,
> no real pricing, no real WhatsApp API, and no guaranteed service availability.
> The current version demonstrates agent role separation, structured reasoning, and
> reproducible orchestration through deterministic local functions. It is designed as
> a prototype layer that can later be connected to LLM tools or real business systems.

---

## 1. Quality of Agent Reasoning

**What it means:** Each agent should demonstrate purposeful, context-aware
decision-making — not just data pass-through.

**How MAS QHomemart addresses it:**

| Agent | Implemented Reasoning (v1.0) |
|-------|------------------------------|
| Customer Triage Agent | Classifies customer chips and user story into a structured `TriageOutput` — problem category, primary space, primary user, inferred constraints, and a normalised need statement |
| Context & Risk Agent | Produces four discrete risk factors with severity levels (`Tinggi` / `Sedang`) and priority order, plus a narrative summary for downstream agents |
| Product Match Agent | Groups demo products into Section A (high-priority risks) and Section B (medium-priority improvements) based on `sectionHint` and `RiskOutput` |
| Service Match Agent | Returns optional service guidance entries for Section C with a `safeAvailabilityNote` — does not claim guaranteed service availability |
| Bundle Strategy Agent | Applies `bundleRules` section definitions to compose a titled, 3-section bundle from product and service matches |
| Staff & Insight Agent | Produces a concise staff summary paragraph and a structured `BusinessInsight` object with problem, product categories, bundle opportunity, and marketing signals |

**Where to look:**
- `agents/` — each agent file contains a JSDoc block explaining its role and the implemented logic
- `data/bundle-rules.ts` — section-based rule configuration driving the Bundle Strategy Agent
- `logs/sample-bathroom-run.ts` — live reproducible sample generated by calling `runBathroomSafetyWorkflow()`

## 2. Collaboration Between Agents

**What it means:** Agents should work together in a meaningful pipeline where
the output of one agent informs the next.

**How MAS QHomemart addresses it:**

The pipeline is implemented as an explicit sequential orchestration in
`workflows/bathroom-safety-workflow.ts`:

```
CustomerInput
  → runCustomerTriageAgent()   → TriageOutput
  → runContextRiskAgent()      → RiskOutput
  → runProductMatchAgent()     → ProductMatchOutput
  → runServiceMatchAgent()     → ServiceMatchOutput
  → runBundleStrategyAgent()   → BundleOutput
  → runStaffInsightAgent()     → StaffInsightOutput
  → createInteractionLogEntry() × 6 steps
  → WorkflowRunResult
```

- Each agent receives structured typed outputs from previous workflow steps — **no shared mutable global state is used**.
- The Bundle Strategy Agent **synthesises two upstream outputs** (ProductMatchOutput + ServiceMatchOutput) into one structured bundle.
- The Staff & Insight Agent **consumes all upstream context** (triage, risks, products, services, bundle) to produce its summary.
- An `InteractionLogStep` is captured after each agent call, producing a 6-entry interaction log.

**Where to look:**
- `workflows/bathroom-safety-workflow.ts` — the complete, runnable orchestrator
- `workflows/interaction-logger.ts` — the log entry factory
- `docs/02-agent-workflow.md` — visual pipeline diagram

## 3. Real-World Business Impact

**What it means:** The system should solve a real, demonstrable business or
social problem — not a toy scenario.

**How MAS QHomemart addresses it:**

| Dimension | Evidence |
|-----------|----------|
| **Social impact** | Addresses fall prevention for elderly occupants — a high-impact household safety concern for older occupants |
| **Commercial signal** | Demonstrates how structured bundling of products and optional service guidance can increase basket relevance — prototype only, no guaranteed revenue increase |
| **Staff efficiency** | The staff summary gives associates a structured briefing so they can assist the customer faster without starting from scratch |
| **Scalability** | The architecture supports multiple problem verticals; bathroom safety is the demo, but the same pipeline can run for lighting, staircase safety, ergonomics, and more |
| **Data signal** | The `BusinessInsight` output (problem category, product categories, bundle opportunity, marketing opportunities) provides a structured signal for management and analytics — prototype only, not connected to real QHomemart reporting |

**Where to look:**
- `data/demo-scenario.ts` — the canonical demo scenario seed
- `agents/staff-insight-agent.ts` — the `StaffInsightOutput` and `BusinessInsight` types

## 4. System Architecture Clarity

**What it means:** A judge should be able to understand the system structure
quickly — where is the UI, where are the agents, where is the data?

**How MAS QHomemart addresses it:**

The folder structure is self-documenting:

```
agents/      ← all agent logic, one file per agent
data/        ← all demo data, clearly separated from business logic
workflows/   ← orchestration, clearly separated from individual agents
logs/        ← interaction log output
types/       ← shared TypeScript types (mas-types.ts)
docs/        ← human-readable documentation (this folder)
app/         ← UI only (Next.js App Router, 8 screens)
```

**Design decisions that support clarity:**
- Kebab-case file names for instant identification
- PascalCase TypeScript types for consistency
- camelCase exported functions following JavaScript conventions
- Each file opens with a JSDoc block explaining its role, phase, and scope

**Where to look:**
- `docs/01-architecture.md` — the full architecture overview with folder map
- `types/mas-types.ts` — all shared pipeline types in one place

## 5. Reproducibility

**What it means:** A judge should be able to clone the repository, run a few
commands, and see the prototype working.

**How MAS QHomemart addresses it:**

```bash
npm install --prefix mas   # install all dependencies
npm run build              # TypeScript check + production build
npm run dev                # start dev server at http://localhost:3000
```

- **No external APIs are required for agent logic.** The local prototype does not require API keys, database access, or environment variables.
- **No environment variables** — no `.env` file needed.
- **No database** — all data is in-memory TypeScript objects in `data/`.
- **No login** — the prototype is immediately accessible.
- **Deterministic output** — `runBathroomSafetyWorkflow()` always produces the same result for the same input; `logs/sample-bathroom-run.ts` exports this as a static, inspectable object.

**Where to look:**
- `docs/03-reproducibility.md` — step-by-step guide with troubleshooting
- `logs/sample-bathroom-run.ts` — reproducible sample output for judges
- Root `README.md` — quick-start section
